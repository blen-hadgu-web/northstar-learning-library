Week 02 · Global token blueprint

A flexible design system for accessible discovery

These tokens establish the color, typography, and spacing rules that will guide every future milestone of the Northstar Learning Library.

  • Archetype: Curation & Discovery Portal
  • Theme: Accessible technology learning
  • Author: Blen Hadgu

Design direction

Token foundation

System goals

  • Use calm, trustworthy colors that support extended reading.
  • Keep text readable in both light and dark environments.
  • Allow headings to scale without depending on viewport units alone.
  • Use a predictable spacing rhythm across future layouts.

How these tokens will be used

Future resource cards, filters, search controls, and comparison widgets will reference these custom properties instead of declaring one-off values.

Perceptual color

OKLCH color system

The background and text pairs are intentionally far apart on the OKLCH lightness axis. The calculated contrast is approximately 15.71:1 in light mode and 16.06:1 in dark mode, exceeding the WCAG AA requirement for normal text.

Light mode

Clear daylight reading

A high-lightness blue-white background is paired with a low-lightness navy text color.

  • Background oklch(97.5% 0.015 250)
  • Text oklch(23% 0.035 255)
  • Primary oklch(48% 0.19 255)
  • Secondary oklch(45% 0.13 170)

Dark mode

Low-glare evening reading

A low-lightness navy background is paired with a high-lightness blue-white text color.

  • Background oklch(17% 0.025 255)
  • Text oklch(94% 0.015 250)
  • Primary oklch(72% 0.15 250)
  • Secondary oklch(76% 0.12 170)

Fluid sizing

Typography scale

Each fluid token combines rem and vw. The rem component ensures browser zoom continues to enlarge the text.

--size-base

How the main-title formula was calculated

  1. Minimum: 1.75rem = 28px at a 375px viewport.
  2. Maximum: 3rem = 48px at a 1440px viewport.
  3. Slope: (48 − 28) ÷ (1440 − 375) = 20 ÷ 1065 ≈ 0.01878.
  4. Convert the slope to viewport units: 0.01878 × 100 ≈ 1.878vw.
  5. Intercept: 28 − (0.01878 × 375) ≈ 20.96px, or approximately 1.31rem.
  6. Final token: clamp(1.75rem, 1.31rem + 1.878vw, 3rem).

Consistent rhythm

Spacing constants

The scale uses relative rem units so spacing responds to the user’s root font-size preferences.

  1. Extra small

    --space-xs: 0.25rem

  2. Small

    --space-sm: 0.5rem

  3. Medium

    --space-md: 1rem

  4. Large

    --space-lg: 2rem

  5. Extra large

    --space-xl: 4rem

Co-piloting record

AI prompts and decisions

Palette prompt

“I am building a curation and discovery portal for accessible technology learning in OKLCH color space. I want a dark/light mode setup. Can you output a CSS :root block with color variables utilizing oklch()? The background and text colors must pass WCAG AA contrast guidelines. Please explain the math behind the Lightness (L) levels you chose for both light and dark mode to guarantee contrast.”

I used the response as a starting point, then selected a light background at L=97.5% with text at L=23%, and a dark background at L=17% with text at L=94%. I verified the resulting contrast before adding the tokens.

Fluid-scale prompt

“I need a CSS custom property for a main title font size that scales fluidly. It should have a minimum size of 1.75rem at 375px viewport width, and a maximum size of 3rem at 1440px viewport width. Can you write the clamp() property using a mix of rem and vw, and break down exactly how the middle viewport-width expression is calculated?”

The calculated expression became clamp(1.75rem, 1.31rem + 1.878vw, 3rem). I retained the rem component to support browser zoom.

Manual audit

Verification checklist

  • 200% zoom: Text grows because all fluid formulas include relative rem values.
  • No overwriting: The root index.html links directly to /week02/index.html.
  • Contrast: Both background/text pairs exceed 4.5:1.
  • Responsive layout: Grids collapse to one column on narrow screens without horizontal page scrolling.
  • Keyboard access: All links have visible :focus-visible indicators.
